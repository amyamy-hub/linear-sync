# 10-03 轮勘误与实测（独立件，本件⛔ 改动任何既有文档）

- 数据库类云节点的「管理面 REST」只覆盖管集群那一半；要读库内数据必须走数据库连接面。本轮三家独立同形（TiDB Cloud / MongoDB Atlas / Turso），后两家的判据原文由被派方逐字引用官方文档。
- 判「某节点不存在」之前，先排除「连接状态」这一层：同一条接口在同一天出现过 可读 → 调不到 → 又可读 的三态翻转。⇒ 可用性结论必须报采样次数与每次的时刻，单次采样⛔ 够定性。
- 权限档位与路径层级不匹配时，某厂商管理 API 给出的是「资源不存在」这一类回答，而⛔ 是「权限⛔ 足」。⇒ 判「钥匙坏了」之前必须先排除「打错了层」。（本轮实测，⛔ 凭据外泄。）
- 客户端连接器的可用性会跨小时漂移。「状态层／可调用层／实打」三态必须分行报；「本机曾注册过」⛔ 等于「现在调得动」。
- 撤卷要留回执：任何把提交件从共享协作面移走的动作，都应在原地留下一行元数据（谁撤的、何时、原件字节数、原因、底稿向谁索取）。否则提交者会把它当成「被人删除」，并为此消耗一整轮去查一个流程动作。
- 共享协作面上的文件名⛔ 能当作「这是交卷」的判据：本轮出现过两枚以其它后缀结尾的真实交卷件，按后缀设的守卫因此全程沉默。
- 本件⛔ 含任何凭据、凭据片段、指纹、锚点原值、账号标识符或项目标识符。

> 附注：本件同时是为下一轮防抄锚准备的一个「只在合并之后才存在」的对象——它⛔ 携带锚值，锚值只住在私有账本里，且必须是「至少两次调用相减」才算得出的派生量（取法口径⛔ 写在本件）。
